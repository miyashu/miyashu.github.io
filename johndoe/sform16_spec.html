SFORM16 要求仕様書(SFORM-2 0.07互換方式・spec2)

MSX-DOS2 / MEGA-SCSI用、FAT16マルチパーティション・フォーマッタの完全仕様(0.09a版とは異なり、隠しFAT12領域を持たない、よりシンプルな構成)。この文書だけで sform16_007.py / write_physical_007.py と同等のプログラムを再現できることを目標にまとめている。

1. 全体構成

Sector 0    : パーティション0(FAT16)。同時にMBRを兼ねる。
Sector xxx  : パーティション1(FAT16)。チェーンの基準点。
Sector xxx  : パーティション2以降(FAT16)。拡張チェーン本体。
  • 隠し領域・MEGASCSI.PNTは存在しない。Sector0自身がそのまま使える実パーティション(パーティション0)である。
  • 全パーティションが均等にFAT16。
  • パーティション総数の上限は32個(MEGASCSI.TBLのレコード数制約)。実運用の上限はMAX_PARTITIONSで別途設定(例: 16個、ファームウェアのドライブ登録テーブル上限に合わせる)。

MBRエントリの構造(16byte):

+0-3  : status/CHS開始(未使用、常に0)
+4    : パーティション種別(type)
+5-7  : CHS終了(未使用、常に0)
+8-11 : 開始LBA(4byte, LE)
+12-15: サイズ(4byte, LE)

4. MBRエントリの規則

4.1 エントリ1(自分自身、0x1BE-0x1CD)

全パーティション例外無く、以下の固定パターン:

type = 0x06 (FAT16)
開始LBA(0x1C6) = 0  (常に自己相対。絶対LBAを入れてはならない)
サイズ(0x1CA) = 自分自身のセクタ数

Sector0(パーティション0)も例外ではなく、開始LBA=0を使う(=「自分自身」を指す)。

4.2 エントリ2(次のパーティション、0x1CE-0x1DD)

基準点は常にパーティション1の絶対LBA(chain_startと呼ぶ)。

  • パーティション0: 次(パーティション1)が存在すればtype=0x05, 開始LBA=chain_start(絶対値), サイズ=0。パーティションが1個しか無い場合は全ゼロ(type=0x00含む)。
  • パーティション1以降(最後以外): type=0x05, 開始LBA=(次パーティションの絶対LBA − chain_start), サイズ=0 (=パーティション1からの相対LBA。直前のパーティションからの相対ではない点に注意)。
  • 最後のパーティション: エントリ2は全ゼロ(type=0x00含む)。

5. FAT・ルートディレクトリ・MEGASCSI.TBL

各パーティションは以下を持つ:

+reserved(1)                     : ブートセクタ
+reserved 〜 +reserved+FATs×sec/FAT-1 : FAT×2本
                                    (各FATの先頭4byteは F0 FF FF FF、残りゼロ)
+その後、root_dir_sec分           : ルートディレクトリ
                                    (先頭32byteにMEGASCSI.TBLのディレクトリ
                                     エントリ。クラスタ2、サイズは§5.1参照。
                                     残りは全ゼロ)
+さらにその後、クラスタ2(1セクタ分書き込めば十分) : MEGASCSI.TBLの実データ
                                    (§5.2参照)

MEGASCSI.PNTは存在しない。

5.1 MEGASCSI.TBLのディレクトリエントリ(32byte)

offset内容
0x00-0x0A"MEGASCSITBL"(11byte、ドット無し8.3形式)
0x0B属性 = 0x27
0x0C-0x190(予約/日時)
0x1A-0x1B先頭クラスタ = 2 (LE)
0x1C-0x1Fファイルサイズ = (パーティション総数)×16 byte (LE)

5.2 MEGASCSI.TBLの実データ(512byte)

16byteレコード×32個。0.09a版(§2.5)と同一形式。

+0    : ドライブ種別(0)
+1    : フラグ(bit6=書込禁止。このspec2では特定パーティションを
        書込禁止にする要件は無いため、通常は0のままで良い)
+2-4  : 開始LBA(3byte, ビッグエンディアン, 絶対値)
+5-7  : サイズ(3byte, ビッグエンディアン)
+8-9  : ブロック長(2byte, ビッグエンディアン) = 512
+10-15: 予約(0)
  • レコード0 = パーティション0(Sector0)、以降レコードNがパーティションN (隠し領域が無いため、0.09a版のような「1つずれる」ことはない)。
  • 実パーティション数を N とすると、レコード N は終端マーカー(開始=デバイス総容量, サイズ=0xFFFFFF, ブロック長=0,予約=00 00 FF FF FF FF)を1つだけ置く。
  • レコード (N+1) 以降、テーブル末尾(512byte)まで00 00 00 00 FF FF FF FF を8byte単位で繰り返して埋める。

この実データは全パーティション(パーティション0含む)のクラスタ2に同一内容を複製する。

7. パーティション計画ロジック

def plan_partitions(total_capacity_sectors):
    plan = []
    remain = total_capacity_sectors
    lba = 0
    while remain >= MIN_PART_SECTORS and len(plan) < MAX_PARTITIONS:
        size = min(TARGET_SECTORS, remain)
        plan.append((lba, size))
        lba += size
        remain -= size
    return plan  # plan[0]=パーティション0(Sector0), plan[1:]=以降

8. 0.09a版との主な違い

項目0.09a版0.07互換(spec2)版
隠しFAT12領域あり(Sector0-19)無し
MEGASCSI.PNTあり(隠し領域のみ)無し
パーティション0の実体隠し領域(空き容量ほぼ0)実際に使えるFAT16パーティション
エントリ1の開始LBA全パーティション常に0全パーティション常に0(同じ)
エントリ2の相対基準最初の拡張パーティションパーティション1
Windows接続時の見え方全パーティションが見える全パーティションが見える(★旧仕様ではSector0のエントリ1がパーティション1を指す設計だったため見えなかったが、この修正版では解消)

9. 既知の注意点

  • CP-004.COM(CP.COMへのパッチ版)には、特定条件下でパーティション番号→ファームウェアレコードの対応にオフバイワンのバグが確認されている。原因はCP-004.COM側の実装であり、本仕様のデータ構造の問題ではない。CP.COM(パッチ無し版)は、MEGASCSI.TBLに正しいサイズ情報がある限り問題なく動作することを確認済み。
  • メディアIDは全セクタを通して統一して 0xF0 を使うこと。
