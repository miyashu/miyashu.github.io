3つのパーティション形式を並べて比較できるようにまとめたもの。いずれも実機ダンプ解析に基づく。フォーマッタの再実装に必要な情報を網羅している。

1. 共通の前提知識

3方式とも、Sector0(またはパーティション自身の先頭)の0x1BE以降に、以下の16byte構造(標準MBRパーティションエントリと同一レイアウト)を1〜2個持つ。

+0-3  : status/CHS開始(3方式とも未使用、常に0)
+4    : パーティション種別(type)
+5-7  : CHS終了(3方式とも未使用、常に0)
+8-11 : 開始LBA(4byte, リトルエンディアン)
+12-15: サイズ(4byte, リトルエンディアン、セクタ数)

エントリ配置は 0x1BE(エントリ1)、0x1CE(エントリ2)。標準MBRは最大4エントリ(0x1BE〜0x1FD)だが、3方式とも実際に使うのは先頭2つまで。

代表的なtype値(Nextorの公式ドキュメントに準拠):

0x00 : 無し(空エントリ)
0x01 : FAT12
0x05 : Extended(CHS、拡張パーティション/EBRチェーンへのリンク)
0x06 : FAT16(CHS)
0x0E : FAT16(LBA)

2. V0.09a 似非ASPI形式

作者による命名。Adaptec系のSCSI I/F(ASPI)との互換性、PC-AT機からの認識を目的とした形式。

2.1 全体構成

Sector 0-19          : 隠しFAT12ミニファイルシステム(MBR兼用)
Sector 20-           : 基本パーティション(FAT16)
基本パーティションの後ろ : 拡張パーティションチェーン(FAT16、可変個数)

隠し領域(Sector0-19)自身も「パーティション0」として扱われる(基本パーティションが「パーティション1」、以降が「パーティション2,3...」)。

MEGASCSI.TBL(実データ、512byte、16byteレコード×32個)

+0    : ドライブ種別(実パーティションは0)
+1    : フラグ。bit6=書込禁止。パーティション0(隠し領域自身)のみ0x40
+2-4  : 開始LBA(3byte, ビッグエンディアン, 絶対値)
+5-7  : サイズ(3byte, ビッグエンディアン)
+8-9  : ブロック長(2byte, ビッグエンディアン) = 512
+10-15: 予約(0)

実パーティション数をNとすると、レコードNは終端マーカー(開始=総容量,サイズ=0xFFFFFF, ブロック長=0, 予約=00 00 FF FF FF FF)を1つだけ置き、以降は00 00 00 00 FF FF FF FFを8byte単位で末尾まで繰り返す。この実データは隠し領域自身に加え、基本・全拡張パーティションのクラスタ2にも複製する。

MEGASCSI.PNT(実データ、512byte)

16byteレコード×最大32個。ASCII 2桁の番号 + スペース14byte。隠し領域自身も含めて連番。隠し領域にのみ存在し、基本・拡張パーティションには置かない。

2.4 エントリ2(次のパーティション)の規則

  • 基本パーティション: 拡張パーティションが1つ以上あればtype=0x05, 開始LBA=最初の拡張パーティションの絶対LBA, サイズ=0。無ければ全ゼロ。
  • 拡張パーティション(最後以外): type=0x05, 開始LBA=(次の拡張パーティションの絶対LBA − 最初の拡張パーティションの絶対LBA), サイズ=0 (最初の拡張パーティションを基準にした相対LBA)。
  • 拡張パーティション(最後): 全ゼロ。

2.5 FAT・ルートディレクトリ・MEGASCSI.TBL

各パーティション(基本・拡張とも)は、ブートセクタ→FAT×2(先頭4byteはF0 FF FF FF、残りゼロ)→ルートディレクトリ(先頭32byteにMEGASCSI.TBLのディレクトリエントリ、クラスタ2、サイズ=パーティション総数×16byte、残りゼロ)→クラスタ2(MEGASCSI.TBLの実データ、§2.2と同一内容を複製)、という構成。MEGASCSI.PNTは置かない。

3. V0.09a MEGA-SCSIネイティブ形式

隠しFAT12領域を持たない、よりシンプルな構成。Sector0自身がそのまま使える実パーティション(パーティション0)である。

3.1 全体構成

Sector 0    : パーティション0(FAT16)。同時にMBRを兼ねる。
Sector xxx  : パーティション1(FAT16)。チェーンの基準点。
Sector xxx  : パーティション2以降(FAT16)。拡張チェーン本体。

3.2 ブートセクタのフィールド(全パーティション共通)

§2.3の表と同一(media ID=0xF0、0x1C-1Dは常に0、0x1E-1Fは18 1Eで0x3Eへジャンプ、拡張BPB使用、等)。ただし以下2点が異なる:

  • 0x1B8-0x1BB(ディスクシグネチャ)は Sector0のみに存在、他のパーティションは全ゼロ。
  • MBRエントリの規則が§3.3の通り(0.09a似非ASPI形式とは基準点が異なる)。

3.3 MBRエントリの規則

エントリ1(自分自身、0x1BE-0x1CD)

全パーティション例外無く: type=0x06, 開始LBA=0(常に自己相対),サイズ=自分のセクタ数。Sector0(パーティション0)も例外ではない。

エントリ2(次のパーティション、0x1CE-0x1DD)

基準点は常にパーティション1の絶対LBA(chain_start)。

  • パーティション0: 次(パーティション1)が存在すればtype=0x05, 開始LBA=chain_start(絶対値), サイズ=0。
  • パーティション1以降(最後以外): type=0x05,開始LBA=(次パーティションの絶対LBA − chain_start), サイズ=0 (パーティション1からの相対LBA)。
  • 最後のパーティション: 全ゼロ。

3.4 FAT・ルートディレクトリ・MEGASCSI.TBL

§2.5と同一構成。全パーティション(パーティション0含む)がMEGASCSI.TBLを持つ(隠し領域が無いため、レコード0=パーティション0自身から始まる)。MEGASCSI.PNTは存在しない。

4. Nextor形式

Nextor(MSX-DOS2の後継OS)が使う、標準的なPC-AT MBR/EBR方式。実機ダンプ解析(8MB/64MB/4GB、複数パーティション構成)により確認。

4.1 全体構成

未パーティション時: Sector0が直接そのままFAT12ボリューム(MBRエントリ無し)
パーティション時  : Sector0がMBR(基本パーティション1個+拡張パーティション
                     1個の、最大2エントリ)
                     拡張パーティション内は、論理パーティションごとに
                     専用のEBR(拡張ブートレコード)セクタ+実データ
                     セクタの組で構成される

SFORM-2系(§2,3)と異なり、パーティション自身のブートセクタにはチェーン情報を一切持たない(MBR/EBRのエントリは全て独立した専用セクタに分離されている)。

4.2 Sector0(MBR)

offset内容
0x00-0x02EB FE 90(未パーティション時も同じ)
0x03-0x0AOEM名 "NEXTOR20"(8byte)
その他BPBフィールド§4.4参照(内包する1パーティション目と同じ規則)
0x1B8-0x1BBディスクシグネチャ
0x1BE-0x1CDエントリ1: 基本パーティション。type=0x01(FAT12)/0x0E(FAT16,LBA)、開始LBA=1(絶対、Sector0直後から)、サイズ=基本パーティションのセクタ数
0x1CE-0x1DDエントリ2: 拡張パーティション。type=0x05、開始LBA=拡張パーティション全体の絶対開始位置、サイズ=拡張パーティション全体のセクタ数(基本パーティション+拡張領域の合計ではなく、拡張領域自体の合計サイズ)
0x1FE-0x1FF55 AA

未パーティション時はエントリ1・2とも全ゼロ(単一ボリュームがSector0直後から直接始まる)。

4.3 EBR(拡張ブートレコード)セクタ

各論理パーティション(基本パーティションの次、パーティション2以降)の実データ直前の1セクタに、独立したEBRを配置する。EBR自身は非実行セクタで、ジャンプ命令・OEM名等のBPBフィールドは全てゼロ。パーティションテーブル部分のみ意味を持つ。

offset内容
0x00-0x1BD全ゼロ
0x1BE-0x1CDエントリ0: このEBRが指す論理パーティション。type=0x01(FAT12)/0x0E(FAT16,LBA)、開始LBA=常に1(このEBR自身からの相対位置。直後のセクタが実データ)、サイズ=そのパーティションのセクタ数
0x1CE-0x1DDエントリ1: 次のEBR。type=0x05(次があれば)、開始LBA=拡張パーティション全体の開始位置(Sector0のエントリ2の絶対値)からの相対LBA、サイズ=0。最後の論理パーティションの場合は全ゼロ
0x1FE-0x1FF55 AA

実データ検証例(8パーティション構成、拡張パーティション開始=絶対LBA 262145):

EBR@Sector262145: entry0=(type01,LBA=1,size=61440)  → 実データ@262146
                  entry1=(type05,LBA=61441)          → 次EBR@262145+61441=323586
EBR@Sector323586: entry0=(type0E,LBA=1,size=1935360) → 実データ@323587
                  entry1=(type05,LBA=1996802)        → 次EBR@262145+1996802=2258947

5. FAT12パーティション時の仕様

§2〜4は主にFAT16パーティションの実機ダンプに基づく。本章はFAT12時の仕様をまとめる。出典は FAT12フォーマット調査.txt(8MB/64MB/256MB SDでの実機ダンプ、2026/09)。

記号の意味:

  • 確認済 実機ダンプで確認済み
  • FAT規格 FATファイルシステム一般の規則
  • 推定 ダンプから導いた規則。観測範囲内では全て一致するが、範囲外は未検証
  • 要確認 未確認

5.1 FAT12共通の規則 FAT規格

項目FAT12FAT16(参考)
FAT種別の判定データクラスタ数 ≤ 40844085 ≤ データクラスタ数 ≤ 65524
FATエントリ長12bit(2エントリを3byteにpacking)16bit
sectors/FATceil((クラスタ数+2)×1.5 / 512)ceil((クラスタ数+2)×2 / 512)
EOC値0xFF8〜0xFFF0xFFF8〜0xFFFF
総セクタ数の格納0x13-14(16bit、最大65535)通常は32bit拡張フィールド

12bit packingの規則(クラスタnのエントリ):

offset = n + n/2 (切り捨て)
n が偶数: 値 = word[offset] & 0x0FFF
n が奇数: 値 = word[offset] >> 4

5.2.2 FAT先頭 確認済

似非ASPI形式: F8 FF FF FF 0F 00 ...   (entry0=0xFF8, entry1=0xFFF, entry2=0xFFF)
ネイティブ形式: F0 FF FF FF 0F 00 ...  (entry0=0xFF0, entry1=0xFFF, entry2=0xFFF)

クラスタ2(MEGASCSI.TBL用)はFAT上で使用中(EOC)になっている。パーティションが1個だけ(ネイティブ形式8MB)でも同じ。MSX-DOS2でファイルを書き込むと、クラスタ3から使われる(書込後 F8 FF FF FF FF FF)。

5.2.3 ジオメトリの決定規則 推定

観測値(ts=総セクタ数、spc=sectors/cluster、spf=sectors/FAT、rd=ルートディレクトリのセクタ数):

全観測値と一致する規則:

spc      = ts/spc ≤ 4096 となる最小の2のべき(観測範囲は4〜16)
clusters = min(4078, floor((ts − 1 − 2×spf − 7) / spc))
spf      = ceil((clusters+2)×1.5 / 512)
rd       = ts − 1 − 2×spf − clusters×spc   (最小7セクタ=112エントリ)

つまり、ルートディレクトリを伸ばして端数セクタを吸収し、データ領域をクラスタサイズでちょうど割り切れるようにする。クラスタ数の上限は4078 (FAT12上限4084より少し小さい)。§2.3のFAT16用例「max clusters 4078」は、この値に由来すると考えられる。

最大セクタ数65288の場合は spc=16、クラスタ4078、rd=15(240エントリ)になる計算だが、未検証 要確認。

5.2.4 MBRエントリ(チェーン)の規則 確認済

似非ASPI形式(64MB例: 隠し0-19, P1@20(16384), P2@16404(32768), P3@49172(63488), P4@112660(11499)):

セクタエントリ1エントリ2
Sector0(隠し)(01, 20, 16384) = P1絶対(05, 16404, 0) = P2絶対
P1@20(01, 0, 16384) 自己(05, 0, 0)
P2@16404(01, 0, 32768) 自己(05, 32768, 0) = P3−P2
P3@49172(01, 0, 63488) 自己(05, 96256, 0) = P4−P2
P4@112660(01, 0, 11499) 自己全ゼロ

チェーンの相対基準はP2(最初の拡張パーティション)で、§2.4と同じ。ただしP1のエントリ2は (05, 0, 0)(最初の拡張パーティションの相対LBA=0)で、§2.4(FAT16)の「最初の拡張パーティションの絶対LBA」とは異なる。

ネイティブ形式(64MB例: P0@0(16384), P1@16384(32768), P2@49152(63488), P3@112640(11519)):

セクタエントリ1エントリ2
Sector0(P0)(01, 20, 32768) ★(05, 49152, 0) = P2絶対
P1@16384(01, 0, 32768) 自己(05, 0, 0)
P2@49152(01, 0, 63488) 自己(05, 63488, 0) = P3−P2
P3@112640(01, 0, 11519) 自己全ゼロ

ネイティブ形式は似非ASPI形式の隠し領域をP0に置き換えた構造になっている(P0↔隠し領域、P1↔基本パーティション、P2以降↔拡張パーティション)。Sector0のエントリ1は、自分自身ではなくP1を指す(サイズ=P1のサイズ)。チェーンの相対基準はP2。これは§3.3(FAT16、基準=P1)とは異なる。

5.2.5 SFORM-2の不具合と思われる点

  1. ★ネイティブ形式 Sector0 の 0x1C6-0x1C9(エントリ1の開始LBA)=20(0x14)似非ASPI形式の値(隠し領域20セクタの直後=P1の開始位置)がそのまま書かれていると考えられる。上記の対応関係から、正しくはP1の絶対LBA(64MB例では16384=00 40 00 00)であるべき。サイズ(0x1CA)は正しくP1のサイズになっているため、開始LBAだけが似非ASPI形式の固定値で上書きされている可能性が高い。
  2. ネイティブ形式でパーティションが1個だけの場合(8MB)、Sector0のエントリ1が (01, 20, 3883322)。P1が存在しないにもかかわらずエントリがあり、サイズ(3A 41 3B 00)はメディア容量を超える無意味な値(未初期化の変数と思われる)。本来は全ゼロであるべき。
  3. 似非ASPI形式でパーティションがP1だけの場合(8MB)、Sector0のエントリ2が(05, 13279, 0)。拡張パーティションが無いのに、P1の末尾(=デバイス末尾)を指している。
  4. MEGASCSI.TBLのファイルサイズ以降(レコードN以降)の内容が不定。空白埋め、SFORM-2のメッセージ文字列の断片、FFパターンなどケースによって異なる(§5.2.6)。未初期化バッファの内容がそのまま書かれていると思われる。ファイルサイズ(N×16byte)の外なので、実害は無い可能性が高い。

これらがMEGA-SCSIの動作に影響するかどうかは 要確認。

5.2.6 MEGASCSI.TBL / MEGASCSI.PNT 確認済

N = パーティション総数(似非ASPI形式は隠し領域を含む)。

意味のある部分(全ケース共通)
rec0 〜 rec(N-1): 各パーティション  (種別00, フラグ, 開始3byte BE, サイズ3byte BE, 0200, 予約0×6)
rec N の +2〜+4 : 最終パーティションの末尾LBA(=最終パーティションの開始+サイズ)
  • フラグ0x40(書込禁止)は似非ASPI形式の隠し領域(rec0)のみ。ネイティブ形式のrec0(P0)は0x00。
  • ルートディレクトリにはMEGASCSI.TBLのエントリのみ(属性0x27、クラスタ2、サイズ=N×16)。PNTのエントリは隠し領域のみ。
  • 全パーティションのクラスタ2に、rec0〜rec(N-1)が同一内容で複製される (似非ASPI形式・ネイティブ形式とも)。
  • パーティションが1個だけでもTBLを作成する(ネイティブ形式8MB: N=1、ファイルサイズ16)。
