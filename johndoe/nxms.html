MEGA-SCSI 用 Nextor 3 ドライバ 開発報告

似非職人工房の MEGA-SCSI には、これまで Nextor のドライバがなかった。そこで Nextor 3 用のドライバを作り、Nextor のカーネルと合わせた 128KB の ROM イメージにして、MEGA-SCSI の SRAM に書き込んで使えるようにした。対象はノーマル版(アスキー製メガロムコントローラ互換)と SCC 付き版(コナミ製メガロムコントローラ使用、通称 WAVE-SCSI)で、SRAM に書き込むインストーラ NXMGINST も作った。実機(FS-A1ST + SCSI2SD V4)で、両機種のインストール、起動、読み書きを確かめた。

その後、オリジナルの MEGA-SCSI の似非 RAM ディスクにあたる「SRAM ディスク」に対応し(ドライバ 0.2)、インストーラが SRAM ディスクを作るようにした(インストーラ 0.3、0.2 までの名前は NXMSINST)。バックアップは SRAM 全体を保存するようにした。これらは「8. その後の更新(ドライバ 0.2 / インストーラ 0.3)」にまとめた。

Nextor 3.0.0 はまだベータ版である。 この報告は Nextor 3.0.0 Beta2 で確かめたものである。「できていること」「できていないこと」、「6. Nextor 3.0.0 Beta2 での注意」に挙げたことはもちろん、挙げていないことも、今後の Nextor の更新で直ったり変わったりすることがある。

1. MEGA-SCSI について

MEGA-SCSI は 似非職人工房 の SCSI カートリッジである。SCSI コントローラ(富士通 MB89352A、以下 SPC)と、カーネルを入れる SRAM を持つ。

  • SRAM は 8KB 単位のバンク切り替えで見える。ノーマル版は ASCII8 型、SCC 付き版は SCC 型(コナミ)のバンク切り替え
  • カーネル(元は MSX-DOS2 ベース)は ROM ではなく SRAM に入っている。そのため、フラッシュ ROM の書き換えなしで、別のカーネルを入れられる
  • SRAM はモデルによって 128KB〜1024KB。カーネルの後ろの SRAM を「似非 RAM ディスク」として A: ドライブに割り当てている(ドライバ 0.2 から「SRAM ディスク」として使える。8 章)
  • SPC は 4000h〜5FFFh にしか出せない(6000h〜7FFFh への書き込みはバンク切り替えになるため)

Nextor 2 / 3 のどちらにも MEGA-SCSI のドライバはなかった。Nextor 3 からはドライバが本体とは別に作られるようになったので、今回は Nextor 3 用として作った。

3. ドライバの仕組み

3.1 SPC の扱い

SPC は 4000h〜5FFFh にしか出せないので、ドライバのバンクを前半(4000h〜5FFFh)と後半(6000h〜7FFFh)に分けた。

  • 前半: Nextor とのやりとり(問い合わせ、読み書きの受付、文字列)。SPC には触らない
  • 後半: SPC を操作するコードをすべて置く。SPC を 4000h〜5FFFh に出している間は前半が見えないので、割り込みを止めて後半のコードだけで動く
  • データの受け渡しは page 1 以外(スタックなど)を使う

SCSI の手順(選択、コマンドの送り方、ステータスとメッセージの受け取り)は、元の MEGA-SCSI BIOS を解析して、それと同じにした。

3.2 読み込みと書き込み

依頼人からの注文は「読み込みはできる限り速く、書き込みは安全に」だった。動画プレイヤーのように、ディスクから連続して読むソフトを想定している。オリジナルの MEGA-SCSI(MSX-DOS2 カーネルベース)では、昔の HDD や MO は問題ないが、SCSI2SD や SCSI2CF への書き込みで問題が出ていた。

  • 読み込み: 1 セクタの先頭で SPC の FIFO にデータが来るのを待ち、あとは 512 バイトを待ちなしで一気に読む(LDI を 512 個並べた「疑似 DMA」)。元の BIOS と同じく、待ちはハードウェアが入れる
  • 書き込み: 8 バイトごとに FIFO が 空になる のを待つ。元の BIOS は「満杯でない」ことしか見ていなかったので、遅い機器(SCSI2SD、SCSI2CF)では 8 バイトの FIFO があふれることがあると考えた

3.3 機器の検出

  • 起動時に SCSI バスをリセットし、ID 0〜6 に INQUIRY を送って機器を探す(LUN 0 のみ)。見つけた機器の名前を表示する
  • 容量は READ CAPACITY で調べ、読み書きは READ(10) / WRITE(10)。セクタ番号は 32 ビットなので、SCSI2SD の設定で 2GB を超える容量にしても使える
  • 取り外しできる機器はメディアの有無を確かめる

3.4 ハングしないための上限

実機で、SCSI 機器がつながっていない、または電源が入っていないと、起動時の検出で止まることが分かった。SPC の状態を待つループに終わりがなかったためである。

  • 待ちのループすべてに上限を付けた
  • 選択が終わらないとき(バスが応答しないとき)は「SCSI bus not responding」と表示して、検出を打ち切る

4. インストーラ NXMSINST(0.2 まで。0.3 からは NXMGINST、8 章)

NXMSINST イメージ [/B[:バックアップ]] [/S:スロット]
NXMSINST /B[:バックアップ] [/S:スロット]
  • MEGA-SCSI を探し、機種(ノーマル版 / SCC 付き版)とイメージが合っているかを確かめてから書き込む
  • /B を付けたときだけ、書き込む前に SRAM の先頭 128KB をファイルに保存する。同じ名前のファイルがあれば上書きするかを聞く
  • 書き込み中は DOS が使えないので、イメージを先にメモリに読み込む。マッパー RAM が足りない分は VRAM の後半 64KB を使う(Nextor の下ではマッパー RAM の空きが少ないため)
  • 書き込んだら照合して、画面に「DONE」(緑)または「WRITE ERROR」(赤)を出し、リセットボタンを待つ

実機で直したこと

  • ノーマル版が見つからない: 別の DOS で起動していて MEGA-SCSI のカーネルが動いていないと、リセット直後のバンクの状態になっていて、識別用の文字列が見えない。自動で探すために別のスロットにも書き込んでみたところ、エミュレータで本体の内蔵 ROM に触れてしまったので、自動での探索はやめた。代わりに /S:スロット でスロットを指定できるようにし、指定したスロットでは SPC があるかを必ず確かめるようにした。SRAM が空でも書き込める
  • 画面が緑一色になる: 書き込みが一瞬で終わるので、メッセージを読む前に画面が緑一色になっていた。SCREEN 0 では VDP の R#7 の上位 4 ビットが文字の色なので、そのまま緑を書くと文字が消えていた。文字の色を残して背景だけを緑 / 赤にし、説明は確認(Y/N)の前に出すようにした
  • バックアップの扱い: 当初は必ずバックアップを取り、既存のファイルは上書きしなかった。試験を繰り返すと邪魔になり、フロッピーに 128KB の空きがないこともあるので、/B を付けたときだけ取り、上書きは確認するようにした

6. Nextor 3.0.0 Beta2 での注意

MEGA-SCSI のドライバではなく、Nextor 3.0.0 Beta2 のカーネルやほかのドライバの動きである。Beta 版なので、今後変わる可能性がある。

6.1 ドライブの割り当て

Nextor 3 では、起動時にメディアがある機器から先にドライブ名が割り当てられるようである。MegaFlashROM SCC+ SD(Nextor 3 用ドライバ)では、SD スロット 2 つと ROM ディスクのドライブ名が、SD カードの有無で次のように変わった。

スロット 1スロット 2A:B:C:
なしなしROM ディスクスロット 1スロット 2
ありありスロット 1スロット 2ROM ディスク
ありなしスロット 1ROM ディスクスロット 2
なしありスロット 2ROM ディスクスロット 1
  • 起動ドライブ(A:)が変わるので、AUTOEXEC.BAT が実行されないことがある。基本的なプログラムを入れた ROM ディスクは常に A: であるのが望ましい
  • 同じドライバでは、デバイス番号の順番も Nextor 2 用から変わっていた(Nextor 2: 1 = ROM ディスク、2 / 3 = SD スロット。Nextor 3: 1 / 2 = SD スロット、3 = ROM ディスク)。デバイス番号から SD スロットを決めているソフトは、Nextor 3 で動かなくなる。順番を固定するか選べるようにしてほしいと、Nextor の Issue #262 で報告した

6.2 Nextor 2 のカートリッジを認識しない

Nextor 3 のカーネルが起動すると、同時に挿した Nextor 2 のカートリッジにはドライブが割り当てられない。

  • SCC 付き MEGA-SCSI(Nextor 3)をスロット 1、似非SDisk(Nextor 2.1.0 Alpha)をスロット 2 に挿すと、SCSI2SD の Nextor 3 から起動したが、似非SDisk にはドライブがなかった。起動時に似非SDisk の初期化メッセージは出ていた
  • MSX-DOS / MSX-DOS2 のドライブ(本体のフロッピーなど)は Nextor 3 でも使える。Nextor 2 では MSX-DOS / MSX-DOS2 のドライブを使えたので、下位互換が一つ減った形である

7. できていること・できていないこと

できていること

  • ノーマル版、SCC 付き版で Nextor 3 が動く
  • SCSI ID 0〜6 の機器の検出、読み書き、32 ビットのセクタ番号
  • 速さ優先の読み込みと、安全側の書き込み
  • SCSI 機器がなくても起動が止まらない
  • インストーラによる書き込み、照合、バックアップ、復元
  • SRAM ディスク(SRAM の 128KB 以降)の読み書きと起動、インストーラでの作成、SRAM 全体のバックアップと復元(8 章)

できていないこと・確かめていないこと

  • 元の MEGA-SCSI カーネルでフォーマットしたディスクの互換性(Nextor の CALL FDISK で作り直す前提)
  • 元のカーネルの似非 RAM ディスクの中身をそのまま使うこと(インストーラが SRAM ディスクに作り直す。元に戻すときは SRAM 全体のバックアップから)
  • 元のカーネルのそのほかの機能(CALL 命令など)
  • SPC を直接操作するソフトのための仕組み(元のカーネル用のソフトは動かない)
  • Nextor 2 用のドライバ
  • 実機での SRAM 256KB / 512KB の版、CALL FDISK での実際のフォーマット、2GB を超える容量、SCSI2SD 以外の機器(HDD、MO、SCSI2CF)、FS-A1ST 以外の機種

8. その後の更新(ドライバ 0.2 / インストーラ 0.3)

8.1 実機で見つかった問題(ドライバ 0.1.1〜0.1.6)

  • 512 バイトでないセクタ: 2048 バイトの MO などは使わない(READ CAPACITY で確かめる)
  • カードの入れ替え: SCSI2SD V4 は、取り外しできる機器の設定にしても、カードの入れ替えを UNIT ATTENTION で知らせなかった。入れ替えを知らせたことのない機器には「分からない」を返し、Nextor に読み直させるようにした。それでも入れ替え直後の読み込みで SCSI2SD が止まることがあったので、取り外しできる機器は 8 バイトごとに時間の上限付きで待つ読み方にし、転送が進まないときはバスをリセットする。依頼人の判断で、SCSI2SD は Hard Drive の設定で使い、カードは電源を切ってから入れ替えることにした
  • 永続ストレージ(device query 8): Nextor 3 の起動前の読み込みに対応した。ところが実機で、電源投入の直後に LED が点いたまま止まることがあった。この読み込みだけがバスリセットなしでコマンドを送っていたためで、最初の呼び出しでバスをリセットし、0.5 秒待つようにした
  • 電源投入直後の起動(0.2.1): SRAM ディスクをフォーマットすると永続ストレージが SRAM に置かれ、SCSI への最初のコマンドが早くなりすぎて、SCC 付き版で止まることがあった(3 回中 2 回)。初期化のバスリセットの後に、タイマーで数えて 2 秒待つようにした(0 回 / 5 回)

8.2 SRAM ディスク(ドライバ 0.2)

  • SRAM の 128KB 以降(256KB 版は 128KB、512KB 版は 384KB、1024KB 版は 896KB)をデバイス 1 にした。SCSI ID 0〜6 はデバイス 2〜8
  • SRAM の大きさは起動時に、バンク 16 に値を書いて、16 / 32 / 64 バンク先に同じ値が現れるかで調べる(元の値は戻す)
  • 読み書きは、4000h〜5FFFh に SRAM の書き込みできるバンクを出して 1 セクタずつ転送する。SCC 付き版は 7FFEh で書き込みを許し、後半 512KB は上位アドレスのビットも立てる
  • フォーマットしていないときは、自動でドライブを割り当てない印を返す
  • 電源を切っても中身が残る。NEXTOR.SYS と COMMAND3.COM を入れればここから起動でき、Nextor の永続ストレージもここに置かれる

8.3 インストーラ 0.3(NXMGINST)

  • 名前を元のインストーラ MGINST に合わせた。ROM の識別子も「NXMG」にしたが、探すときは「NXM」の 3 文字で探すので、0.2 までで入れたものも見つかる
  • SRAM ディスクを作る: 256KB 以上の版では、Nextor の ROM と一緒に SRAM ディスクをフォーマットし(CALL FDISK と同じ形の FAT12 パーティション)、実行したフォルダに NEXTOR.SYS と COMMAND3.COM があれば書き込む。MGINST が似非 RAM ディスクを起動ディスクにしたのと同じである。中身があるとき(元のカーネルの似非 RAM ディスクや、前に作った SRAM ディスク)は、フォーマットするかを聞く。/N を付けると SRAM ディスクには触らない
  • SRAM 全体のバックアップ: 依頼人から「元のカーネルは 64KB で、残りに似非 RAM ディスクの FAT などが入っている。128KB だけ書き戻すのは怖い」と指摘があった。実際、元のカーネルの似非 RAM ディスクは SRAM の 64KB 目から始まる(1024KB 版で 960KB)。そこで /B は SRAM 全体(1024KB 版なら 1MB)を保存し、書き戻すときも全体を戻すようにした。128KB 以降はファイルから 8KB ずつ書いて照合し、最後に先頭 128KB を書く。保存に失敗したときは途中までのファイルを消す。1MB はフロッピーに入らないので、SCSI2SD などに保存する(SRAM ディスクや似非 RAM ディスク自身には置けない)
  • ファイルの読み込みは、バンク(8KB)に入るだけまとめて読む。1 セクタずつだとフロッピーが 1 回転ずつ待ち、10 秒ほど余計にかかった

8.4 確かめたこと

  • 実機(ノーマル版 / SCC 付き版 1024KB): CALL FDISK での SRAM ディスクのフォーマット、SRAM ディスクからの起動、720KB のファイルを MegaFlashROM SCC+ SD → SRAM → SCSI2SD → MegaFlashROM と逆順にもコピーして照合(Z80 / R800)、電源を切っても中身が残ること、SCSI2SD なしで SRAM ディスクから起動
  • 実機(インストーラ 0.3、両機種): SRAM ディスクの作成(フォーマットの確認に Y / N、/N、元のカーネルから)とそこからの起動。SRAM ディスクに書いたファイルを SD カードに書き戻して元のファイルと一致
  • 実機(SRAM 全体のバックアップ、両機種): Nextor の上で保存 → 元のカーネルのダンプを書いて、元のカーネルと似非 RAM ディスクが動く(CHKDSK エラーなし) → 保存したものを書き戻して、Nextor と SRAM ディスクに戻る(CHKDSK エラーなし)
  • 実機(ノーマル版 128KB): インストール(SRAM ディスクは作らない)
  • openMSX: ノーマル版 128KB / 256KB / 512KB / 1024KB、SCC 付き版 1024KB で、SRAM ディスクの作成、バックアップと復元、SRAM ディスクからの起動と読み書き。ノーマル版 1024KB の最後のバンクは openMSX では SPC と区別されず試せないが、実機では読み書きできた
